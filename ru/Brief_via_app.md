# Brief: running application

## Запущенное приложение[​](#запущенное-приложение "Прямая ссылка на этот заголовок")

`/mcp` приложения даёт доступ к его развёрнутому коду (`lsfusion_files_*`), данным и действиям (`lsfusion_eval`, `lsfusion_exec`). [Код eval](/ru/Eval_EVAL.md) может вводить локальные элементы и вызывать загруженные, но не меняет постоянную структуру проекта: для этого нужны правка исходного кода и развёртывание, вне этого вида доступа. Настройки и сохранённая настройка форм — это хранимые данные, они меняются в работающем приложении.

## Вызов через `/mcp`[​](#вызов-через-mcp "Прямая ссылка на этот заголовок")

`Authentication.currentUser[]` — учётная запись MCP-токена, возможно общая запись интеграции, а не тот, кто просит. Отвечать на диалог некому: `ASK` получает YES без вопроса пользователю, `INPUT` не поддерживается, интерактивная форма не открывается. Отбрасывание сессии вызова не отменяет того, что вызванные действия применили сами, и эффектов вне базы данных.

## Сохранённая настройка[​](#сохранённая-настройка "Прямая ссылка на этот заголовок")

[`SystemEvents`](/ru/System_SystemEvents.md) хранит код настройки для всех пользователей и для одного:

* формы — операторы `EXTEND FORM` и `DESIGN` — в `dataExtendCode[Form]` и `dataExtendCode[Form, User]`, объединяемых и компилируемых при создании формы;
* приложения — операторы `NAVIGATOR` и `WINDOW` и формы, действия и свойства, нужные добавленным элементам, — в `dataExtendCode[]` и `dataExtendCode[User]`, объединяемых и компилируемых при запуске подключения пользователя. Объявленное в нём видят скрипты, которые вычисляют вызовы этого пользователя.

Об ошибке компиляции сообщается, и форма или навигатор клиента приходят без настройки. `lsfusion_eval` читает фрагмент через `RETURN` и записывает его целиком с `APPLY`. Уже открытое остаётся прежним: изменение формы видно, когда форма создаётся заново, изменение приложения — когда заново запускается подключение. Через `/mcp` пользователь открывает форму снова или перезапускает клиент, на странице — см. [пересоздание формы](/ru/Brief_via_webapp.md).

## Клиентские действия через `/mcp`[​](#клиентские-действия-через-mcp "Прямая ссылка на этот заголовок")

У вызова через `/mcp` нет клиента пользователя: в самом вызове `MESSAGE` лишь возвращается вызывающему в `messages`, а форма или файл открыться не могут. Чтобы выполнить клиентское действие в клиенте подключённого пользователя, скрипт передаёт его [подключению](/ru/System_SystemEvents.md) этого пользователя (`SystemEvents.Connection`) через [`NEWEXECUTOR ... CLIENT`](/ru/NEWEXECUTOR_operator.md) с вложенным обычным `NEWTHREAD`:

```
FOR userLogin(Connection c) = 'alice' AND connectionStatus(c) = ConnectionStatus.connectedConnection DO
    NEWEXECUTOR {
        NEWTHREAD MESSAGE 'The report is ready';
    } CLIENT c NOWAIT;
```

Здесь берутся подключения пользователя с логином `alice`. У пользователя может быть несколько активных подключений — вкладки браузера, десктоп-клиент, — и `FOR` проходит по каждому. `lastActivity[Connection]` показывает самое недавнее. Переданное действие выполняется на сервере в новой сессии навигатора этого подключения, а не в сессии открытой формы. Его интерактивные операторы обращаются к интерфейсу этого клиента, а `Authentication.currentUser[]` в нём — пользователь подключения. `NOWAIT` возвращает управление сразу, не дожидаясь завершения действия; `WAIT` ждёт, с необязательным таймаутом.

На странице приложения для собственного клиента пользователя это не нужно: там [eval и exec](/ru/Brief_via_webapp.md) уже выполняются в нём. Передача подключению остаётся там только для редкого случая — выполнить действие в другой вкладке или другом клиенте пользователя.
