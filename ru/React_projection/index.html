Проекция формы

Проекция формы — состояние формы, открытой в интерактивном представлении, в том виде, в котором его получает представление React: группы объектов, свойства и компоненты дизайна в виде объектов JS.

props.data — проекция формы, своя у каждого контейнера с компонентом React: в ней только то, что этот контейнер рисует или размещает, поэтому второй React-контейнер формы получает отдельную проекцию, а вместе с ней и собственный контроллер.

Представление читает только части своего контейнера и меняет их через члены своего контроллера; то, что рисует другой контейнер или платформа, оно меняет через контроллер формы, по именам (между контейнерами). Общее у контейнеров — сама форма: её текущие объекты, сортировки, фильтры и сессия, поэтому фильтр или текущий объект, изменённые в одном контейнере, видны в другом так же, как в стандартном клиенте.

Страница может состоять из нескольких контейнеров с компонентом React, разложенных обычными контейнерами DESIGN, и другой модуль по-прежнему может дополнить такую страницу из DESIGN. Изменение перерисовывает только контейнеры, чьи проекции изменились. Контейнер в неактивной вкладке или в свёрнутом контейнере не читается, пока не показан, если только то же самое не читает показанная часть формы (Скрытое представление).

Записи, части и узлы​

Каждое свойство, группа и контейнер, которые включает проекция, — это объект в data: значение читается как .value, его атрибуты — как соседние поля, а атрибуты колонки списочного свойства — из data.<group>.<prop>. Записи контейнера для свойств и компонентов — данные дизайна: каждая из них есть с самого начала, а показывает ли её форма сейчас, указывает её поле hidden, а не то, есть ли она.

data содержит группу, когда представление рисует ЧАСТЬ этой группы, и содержит ровно те части, которые рисует. Часть группы или дерева проецируется — её данные и члены контроллера, которые её меняют, — в тот React-контейнер, где находится компонент этой части, в узел её группы или дерева:

КомпонентЧастьУзел

У группы в виде PANEL есть только её панельные свойства и группы фильтров: строк, сортировок, пользовательских фильтров, управляющих элементов фильтров и тулбара нет — платформа их для неё тоже не показывает.

data.<group>.properties называет каждую запись СВОЙСТВА, которая есть в этом узле, показываемую или нет, в порядке формы, — а не всё, что на узле лежит: там есть и то, что определяет сама проекция (list, byKey, keys, options, orders), и это известно по имени, а не обнаруживается.

Место компонента​

Место компонента находится подъёмом вверх от его контейнера: ответ — контейнер с компонентом React, а контейнер с собственным представлением — custom = NULL или свой custom — подъём обрывает, потому что всё под ним рисует это представление. Есть ли собственное представление у самого компонента, решает только то, какая запись у него там будет — его содержимое или запись, которая его подписывает, — но никогда не то, где.

Поэтому MOVE панельного свойства и решает, какой движок его рисует: внутри кастомного контейнера его рисует React по data, вне его — платформа, там, где оно теперь стоит, и из data оно уходит.

Компонент свойства находится только в одном контейнере, поэтому свойство уровня формы, которое показывают два контейнера, добавляется дважды, под двумя алиасами, по одному в каждый контейнер.

Контейнер с собственным custom внутри того, что рисует компонент React, — другим компонентом React, HTML-шаблоном, '' — этим компонентом не рисуется: его рисует его собственное представление, а внешний компонент размещает его так же, как любой другой дочерний компонент, который рисует платформа. Так же и таблица, тулбар, управляющие элементы фильтров, группа фильтров или фильтр по свойству с собственным компонентом React.

Узел со строками​

Представление, которое рисует строки — грид лежит внутри кастомного контейнера, и ни у него самого, ни у контейнера между ними нет собственного представления, так что строки рисует React из data, а не платформа, — получает props.data.<g> равное { list, byKey, keys, options, orders, properties } для этого SID группового объекта g, где:

  • list — массив строк в порядке отображения. Число строк — это list.length.
  • byKey сопоставляет строковому ключу строки тот же объект строки. Ключи byKey — это данные приложения, поэтому он создаётся БЕЗ прототипа: строка с ключом __proto__ лежит в нём обычной записью, а byKey.hasOwnProperty и прочие методы Object.prototype вызвать не на чем — читайте через byKey[k], а проверяйте через k in byKey или Object.keys(byKey).
  • keys — массив этих строковых ключей в том же порядке.
  • options — собственные опции отображения группы.
  • orders — сортировки группы. У группы дерева orders нет: сортировки дерева лежат в его собственном узле.

Там, где представление рисует строки, list, byKey и keys присутствуют все: пока у группы нет строк — например, до прихода её первых строк, — они пусты, поэтому представление читает props.data.<g>.list напрямую, без проверки на отсутствующее поле.

Грид (или дерево), который форма скрывает через SHOWIF, говорит об этом в своей записи, data['GRID(g)'].hidden — у дерева это data['GRID(TREE t)'], одна на все его группы, — а его строки остаются такими, какими сервер прислал их последний раз, как их хранит и грид самой платформы, — пока грид скрыт, сервер может их не обновлять, — поэтому рисуйте их, только пока грид не скрыт.

Каждая строка содержит:

ПолеЗначение
keyСтабильный публичный идентификатор строки — используется как ключ React
currentЯвляется ли строка текущей в своей группе (true или false)
<integrationSID>Каждое списочное свойство — объект { value, ...атрибуты ячейки } по интеграционному SID этого свойства; значение читается как .value
objectsНепрозрачный дескриптор строки, по которому контроллер адресует строку
background, foreground, selectedСобственные опции отображения строки: её цвета фона и текста и признак выделения

Узел без строк​

Там, где представление не рисует строки, у узла нет list, byKey и keys, как нет и options и orders (сортировок группы — порядка, в котором рисуются эти строки): здесь нет строк, о которых они могли бы говорить, и одним из этих имён может называться панельное свойство группы.

Группа в виде PANEL не рисует строки нигде — сервер их ей не присылает, только текущий объект, — поэтому её узел такой везде, где бы ни был её грид, включая контейнер, в котором он лежит: её панельные свойства и никакого change(row).

Группа, ни одной части которой представление не рисует, отсутствует в props.data целиком (props.data.<g> — undefined): контейнер, просто стоящий рядом с платформенным гридом, не получает ничего, как и тот, который лишь обрамляет его (MOVE GRID(g) { custom = NULL; } — там строки рисует платформа, поэтому контейнер получает запись, называющую то, что он размещает, и никаких строк; тот, в котором стоит и FILTERS(g), получает пользовательские фильтры группы).

Запрос строк у <List>, когда их здесь нет, — ошибка в представлении, и он бросает исключение: представление показывает причину на своём месте и в консоли.

Свойства и действия​

Панельные свойства группы являются полями узла группы в том контейнере, в котором находится само свойство, по интеграционному SID. Верхний уровень props.data — это узел пустой группы (уровень формы): каждое свойство пустой группы является полем props.data напрямую, по своему интеграционному SID. Атрибуты колонки списочного свойства тоже являются полем группы, в data.<g>.<prop> — по одной записи на колонку, — а его построчное значение и атрибуты ячейки лежат в каждой строке.

Действия, которые рисует React, проецируются так же, как свойства: действие, добавленное на группу, является полем каждой строки (списочное действие) или узла группы (панельное действие) — объектом своих атрибутов, как свойство, — поэтому controller.<group>.<action>.exec(row) его выполняет (.exec() панельного действия строку не принимает). Поле value у него тоже есть, но ничего не несёт. У действия, которое рисует платформа, есть только запись, а выполняет его кнопка платформы.

COLUMNS и совпадающие имена​

Свойство, сгруппированное по колонкам (COLUMNS), спроецировать нельзя: его значения адресуются ключом «строка и колонка», а всё здесь — строка list, запись byKey, имя на контроллере — означает одну строку. Поэтому React-контейнер не может нести такое свойство — ни колонкой строк, которые он рисует, ни панельным свойством или свойством пустой группы, стоящим в нём: такая форма отклоняется при построении с указанием свойства.

В остальной части формы оно остаётся как есть, а у React-представления просто нет для него имени: контроллер включает то же, что и проекция, поэтому у неспроецированного нет члена. Если представлению нужны эти значения, объявите обычное свойство.

Если имя в представлении не выделяет одно свойство, форма отклоняется так же: два свойства спроецированной группы могут делить интеграционное имя, только если их записи находятся в разных контейнерах, и тогда каждое представление имеет в виду то, что содержит его собственный узел. В одном контейнере так нельзя — одна запись и один член не могут означать два свойства; и нигде нельзя, в том числе со свойством, которое рисует платформа, если представление рисует часть, которая называет свойство группы (Зарезервированные имена). Задайте одному из них явный EXTID.

Постраничное чтение​

list содержит прочитанные строки — до трёх страниц, а не все строки группы. Вид представления группы, отрисовываемой контейнером React, остаётся таблицей, и группа читается постранично, но, поскольку сама таблица не отображается, размер страницы не подбирается под видимые строки — действует серверный размер страницы по умолчанию (50 объектов), так что в list до 150 строк.

Представлению, которое показывает все строки группы — календарю, доске, карте, — задайте в блоке OBJECTS опцию PAGESIZE 0 (читать все объекты) либо явный размер страницы.

Число прочитанных строк — list.length, а не число строк, пропущенных фильтрами группы, поэтому при постраничном чтении одна проекция этого числа не даёт.

Зарезервированные имена​

Резервирование зависит от содержимого строки или узла:

ГдеЧто зарезервировано
Строкаkey, current, objects, background, foreground, selected — у строки дерева ещё и parent, hasChildren, expanded, loading
Узел группы, где бы он ни былproperties, change

Собственные current и expandCurrent дерева и его сортировки, там, где рисуются его строки, а также его пользовательские фильтры, управляющие элементы фильтров и тулбар находятся в его узле. В контейнере, содержащем лишь панельное свойство группы, имён остальных частей нет, поэтому свойство с именем list там ничем не отклоняется.

__proto__ зарезервировано везде: присваивание по этому имени не добавляет поле, а заменяет прототип объекта. Объекта meta нет нигде.

Форма, в которой проецируемый интеграционный SID занимает зарезервированное имя или два проецируемых элемента занимают одно имя на одном уровне данных, отклоняется с явной ошибкой при её построении. Как и форма, в которой группа, строки или пользовательские фильтры которой рисует представление или тулбар которой с суммой рисует оно, имеет два свойства с одним именем где-либо на форме, в том числе на нарисованном платформой: сортировка, условие и getSum тулбара называют свойство группы этим именем. Задайте одному из этих свойств явный EXTID или переименуйте его.

Свойство, которое такой контейнер рисует или размещает, вообще должно иметь имя - представление достаёт его только по этому имени, и запись, и <Platform>: объявленное с NOEXTID отклоняется так же - задайте ему EXTID.

Пустое имя или имя с точкой тоже отклоняется — составное имя, o.note, делится по последней точке, — как и группа из нескольких объектов без собственного имени, OBJECTS (d = X, t = Y), там, где представление включает её часть: её SID — имена объектов через точку, поэтому назовите её, OBJECTS pair = (d = X, t = Y).

Свойство или действие, которое рисует платформа, называется так же, как любое другое, и всё это относится и к нему.

Чтение проекции​

Компонент читает проекцию одним из двух способов, и выбор — про то, кто перерисовывается при изменении данных.

props.data — снапшот целиком. Компонент перерисовывается — с новым data — при любом изменении своей области и рисует всё, что рисует, из нового снапшота. Для небольшого представления этого достаточно: никаких хуков, чистая функция от данных — так написан OrderBoard. Так же читается и вся область целиком — перечисляются её верхние записи, читаются контейнеры. useData() без селектора возвращает тот же снапшот.

useData(selector) подписывает компонент на часть проекции: он перерисовывается, только когда меняется ссылка selector(data), — поэтому селектор должен возвращать то, что в проекции уже есть (узел группы, строку, запись, значение), и никогда не собирать внутри себя новый объект или массив: такой результат отличается при каждом чтении и приводит к бесконечной перерисовке.

Благодаря структурному переиспользованию — не изменившийся узел, строка или запись сохраняют прежнюю ссылку — именно это позволяет компоненту перерисовываться, только когда меняется то, что он читает: компонент, подписанный на узел группы (useData(s => s.o)), не перерисовывается при изменениях в остальной области, а компонент строки, подписанный на свою строку (useData(s => s.o.byKey[rowKey])), — при изменениях других строк.

Корень — исключение: платформа передаёт ему новый props.data при каждом изменении, поэтому он перерисовывается, на что бы ни был подписан, а то, что он рисует ниже, пропускает перерисовку, только если оно мемоизировано (React.memo) и не получает data.

useController() возвращает тот же controller, который корень получает параметром, — его идентичность не меняется за время существования корня, поэтому он безопасен в зависимостях и замыканиях, и передавать его вниз параметром так же правильно.

useData и useController читают тот корень, внутри которого находится компонент, независимо от того, относится ли этот корень к форме. Platform и usePlatform помещают то, что платформа рисует сама, поэтому одинаково служат и контейнеру формы, и окну навигатора. А построенное на групповой и строчной форме проекции — List, BucketScope, useBucket, Buckets, useSeekOnScroll — существует только для форм: оно обращается к data.<group>.list / .byKey / .keys, чего нет ни у корня другого вида, ни у представления формы, которое строк этой группы не рисует.

Опции отображения​

Для каждого свойства, добавленного на форму, платформа вычисляет смысловые опции отображения: заголовок, изображение, цвет фона и цвет текста, состояние «только чтение» или «отключено», комментарий, текст в пустой ячейке, всплывающую подсказку. Они берутся из дизайна свойства и из зависящих от данных опций блока свойств и действий (HEADER, IMAGE, BACKGROUND, FOREGROUND, READONLYIF, OPTIONS и остальных), поэтому опция, зависящая от данных, вычисляется заново для каждой строки.

Классы элементов и шрифты стандартного клиента не проецируются: компонент React сам определяет свои CSS-стили. background и foreground проецируются — это выделение из BACKGROUND / FOREGROUND, зависящий от данных бизнес-сигнал, а не тема, которой должны владеть собственные CSS-стили компонента.

Расположение опций​

Для свойства, которое контейнер React отрисовывает сам, смысловой результат проецируется в data соседними полями рядом со значением свойства, поэтому представлению не нужно вычислять его заново.

Проекция следует тому, что описывает опция, — колонку целиком, одну ячейку или строку:

ГдеЧто содержит
data.<g>.<integrationSID>Для свойства, показываемого в таблице, — атрибуты его колонки, по одной записи на всю колонку: caption, image, footer, comment, tooltip, defaultValue и hidden, пока форма его скрывает
data.<g>.list[i].<integrationSID>Одна ячейка свойства таблицы — её value для этой строки и атрибуты ячейки, вычисленные для этой строки: readOnly, disabled, background, foreground и остальные
data.<g>.list[i]Собственные опции строки, прямо на строке: background, foreground, selected
data.<g>options — пользовательские опции группы, там, где представление рисует её строки; properties — записи СВОЙСТВ, которые содержит этот узел, показываемые или нет
data.<integrationSID>Свойство пустой группы — его value, атрибуты и hidden, пока форма его скрывает; свойство, которое рисует платформа, — запись, которая его подписывает, без value
data.<componentSID>Запись любого другого компонента, который это представление рисует или размещает: его caption и image, если они у него есть, и hidden, пока форма его скрывает, по идентификатору компонента дизайна — всегда на верхнем уровне, во что бы компонент ни был вложен

В data.<g>.<integrationSID> для панельного свойства группы лежат value свойства и его атрибуты, вычисленные для текущего объекта, и hidden, пока форма его скрывает. Пока текущего объекта у группы нет, value пустое, а запись остаётся, как и в панели самой платформы. Для свойства, которое рисует платформа, там лежит запись, которая его подписывает, без value.

В data.<componentSID> лежит запись:

  • контейнера, объявленного через NEW или сгенерированного, как PANEL(o) или TOOLBAR(o);
  • грида, как GRID(o), или дерева, как GRID(TREE t);
  • панели инструментов, как TOOLBARSYSTEM(o);
  • фильтра по свойству, как FILTER(name(o));
  • любого компонента, который рисует платформа, кроме свойства.

Запись есть всегда; у показанного компонента без заголовка и изображения она пуста.

Каждый атрибут присылается в одном месте, уже вычисленным: статическое значение из дизайна свойства и его построчный результат BACKGROUND / READONLYIF / … сводятся в одно действующее значение до того, как его получит представление, поэтому представление читает атрибут непосредственно из его записи, и никогда не объединяет запись колонки с записью строки. Атрибуты списочного свойства на всю колонку — caption, image, footer, comment, tooltip, defaultValue — находятся в узле его колонки data.<g>.<prop>, а его построчное значение и атрибуты ячейки, которые могут меняться по строкам, — в ячейке data.<g>.list[i].<prop>:

const caption = props.data.o.sum.caption;   // атрибут колонки, один на всю колонку
const cell = row.sum;                        // { value, background, readOnly, ... } для этой строки

Динамический IMAGE свойства сервер вычисляет один раз для ключа колонки с использованием текущего объекта, а динамический IMAGE действия — для каждой строки. Проекция сохраняет это различие: изображение свойства находится в узле его колонки data.<g>.<prop>, а изображение действия — в ячейке его строки data.<g>.list[i].<action>.

Опция, для которой платформа ничего не вычислила, отсутствует: у свойства без BACKGROUND нет background в записи его ячейки, а у строки, для которой не вычислено ни одной опции строки, нет background, foreground и selected.

Скрытые свойства​

SHOWIF управляет самим свойством, и меняет он поле hidden записи, а не то, есть ли запись. Когда он скрывает колонку таблицы, запись колонки говорит hidden: true, а ячейки колонки остаются в строках без value. Когда он скрывает панельное свойство или свойство пустой группы, его запись говорит hidden: true и не имеет value.

Свойство, которое форма скрывает при открытии, остаётся hidden, пока не будет прислано впервые. Если нужно отличить скрытое свойство от свойства со значением value, равным null, читайте hidden. У записи, которую форма показывает, поля hidden нет вовсе — как нет и любой опции, для которой платформа ничего не вычислила.

Остальные (background, foreground, readOnly, disabled, placeholder, pattern, regexp, regexpMessage, valueTooltip, options, select, loading) — атрибуты ячейки, в ячейке каждой строки data.<g>.list[i].<prop> рядом с её value. Сама строка содержит background и foreground — цвета строки целиком — и selected, равное true, пока строка входит в выделенный диапазон, и отсутствующее иначе, — прямо на строке, а не внутри какой-либо записи свойства.

function Row(props) {
    const r = props.row;
    const sum = r.sum;              // { value, readOnly, disabled, background, foreground, ... }
    return (
        <div className="order" style={{ background: r.background }}>
            <span>{r.number.value}</span>
            <input value={sum.value} readOnly={!!sum.readOnly} disabled={!!sum.disabled}
                   style={{ background: sum.background, color: sum.foreground }} />
        </div>
    );
}

Выбор​

Свойство, которому в FORM задан SELECT, показывается как выбор среди всех его возможных значений: объектов, на которые может указывать ссылка, по их представлению (статусов, которые может иметь заказ, по их именам), или, для выбора нескольких значений, объектов, которые можно отметить (меток заказа). Внутри контейнера, который рисует компонент React, такое свойство компонент рисует сам, и запись свойства несёт сразу все его варианты:

FORM orders 'Orders'
    OBJECTS o = Order PANEL
    PROPERTIES(o) number READONLY, nameStatus SELECT, tags SELECT
;

DESIGN orders {
    NEW card FIRST { custom = 'OrderCard'; MOVE BOX(o); }
}
data.o.nameStatus = {
    value: 'New',              // значение выбранного варианта
    type: 'string',
    select: {                  // то, что добавляет SELECT
        list: [                // все варианты, в их порядке
            { key: 581, value: 'New', selected: true },
            { key: 583, value: 'Done' },
            { key: 584, value: 'Lost' }
        ]
    }
}
data.o.tags = {
    value: 'red',              // собственное значение свойства: значения отмеченных вариантов, склеенные
    type: 'string',
    select: {
        multi: true, separator: ', ',
        list: [{ key: 577, value: 'blue' }, { key: 576, value: 'green' },
               { key: 575, value: 'red', selected: true }]
    }
}

select — то, что SELECT добавляет к записи, одним полем. У каждого варианта его list есть:

  • key — идентификатор объекта, которым он является (у варианта из нескольких объектов, как у выбора по группировке по нескольким объектам, — строка из их идентификаторов), один и тот же, пока вариант есть, ключ для React;
  • value — представление, которым он показывается, текст;
  • selected, пока он выбран.

У выбора одного значения value записи — значение выбранного варианта, это и есть значение свойства; если ничего не выбрано, ни один вариант не selected, а value — null.

У выбора нескольких значений, select.multi: true, value — представления отмеченных вариантов в порядке списка, склеенные select.separator, и null, если ничего не отмечено. Для обычного tags(o) = GROUP CONCAT name(t) IF in(o, t), ', ' ORDER name(t), t это собственное значение свойства; если свойство — что-то другое над вариантами — выражение над GROUP CONCAT (upper(tags(o))), OVERRIDE, — это всё равно отмеченные варианты, склеенные: 'green, red', тогда как у свойства 'GREEN, RED'.

select.separator — разделитель его GROUP CONCAT, если он литерал, не локализуемый, у OVERRIDE нескольких — тот, которым склеивают они все, и запятая, ', ', иначе — если он вычисляется или локализуется либо ветки OVERRIDE склеивают разными.

select.notNull: true говорит, что значение должно быть, поэтому представление не даёт его очистить. Тип элемента выбора — см. SELECT.

У колонки select — в ячейке каждой строки, row.nameStatus.select: выбранное у каждой строки своё. Представление варианта рисуется через <Caption>: оно может быть HTML.

Свойство изменяется выбранным, через change его члена:

  • У выбора одного значения change принимает вариант — элемент select.list или его значение: change('Done'), — а null очищает значение; значение, которое должно быть, не очищается. Уже выбранный вариант ничего не меняет, и ничего не отправляется.
  • У выбора нескольких значений — их значение, как его даёт value, — представления, склеенные select.separator: change('green, red'), — или массив вариантов, отмеченных с этого момента, элементов select.list или их значений: change(['red', 'green']); null, [] и '' снимают все отметки.
    • Значение, которое разбивается на представления больше чем одним способом — представление содержит разделитель или сливается с ним на краю, либо разделитель пустой, — отклоняется: тогда передавайте массив.
    • Отдельный вариант — элемент select.list — отмечается или снимается: противоположно тому, что ячейка показывает сейчас, с выбором, на который ещё нет ответа.
  • Значение, которого нет ни у одного варианта, отклоняется, как и значение, которое есть у нескольких, — у вариантов может быть одно представление: тогда передавайте сам вариант.

Выбор отправляется так же, как его отправляет собственный элемент платформы, по одному варианту, выбранному или больше не выбранному: записывается ссылка — status(o) получает выбранный статус, — а у выбора нескольких значений условие каждого отмеченного или снятого варианта, in(o, t). Вызов, который отмечает и снимает несколько вариантов, отправляет их одним запросом, сначала отметки.

Представление показывает выбор сразу — в select.list и в value, — ячейка говорит loading до ответа, а ответ приносит заново прочитанные варианты. В пакете выбор идёт вместе с остальным.

Варианты читаются и приходят так же, как значение: при открытии формы и снова всякий раз, когда меняется то, от чего они зависят, — их представления, какие это объекты, что выбрано, — или текущий объект, или строки; каждый раз варианты ячейки приходят целиком. Там, где собственный элемент платформы получает только выбранные варианты, а остальные ищет по введённому тексту, — при многих вариантах, — представление всё равно получает их все.

Платформа строит элемент выбора и сама — для ссылки с уникальным представлением или для выбора нескольких значений; свойство, которое рисует компонент React, этого не получает: варианты в его записи есть только там, где выбор задан — SELECT в форме или в объявлении свойства.

select в дизайне всегда называет элемент платформы, поэтому задаётся вместе с custom = NULL. Вместе с NOCUSTOM — PROPERTIES(o) nameStatus SELECT 'buttonGroup' NOCUSTOM — платформа рисует свой элемент выбора, а компонент размещает его через <Platform name/>, как любой дочерний компонент, который рисует платформа, построчно — в строках, которые он рисует.
