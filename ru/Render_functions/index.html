Функции отображения

Функция отображения — функция JavaScript, рисующая пользовательское представление: вместо платформы она рисует строки группы объектов или значение свойства формы в интерактивном представлении.

Её называет опция CUSTOM группы в блоке OBJECTS или свойства — в блоке PROPERTIES либо среди опций свойств в его объявлении. Называет её и атрибут custom таблицы группы GRID(o) или компонента свойства в дизайне формы (DESIGN). Вместо такой функции в тех же местах можно назвать компонент React (Компонент React в CUSTOM).

Функция возвращает объект из функций, которые вызывает платформа: render, update и необязательной clear. Функции отображения вызывает только веб-клиент.

Функция отображения​

Например, функция отображения группы объектов itemCards возвращает объект из двух функций, render и update:

function itemCards() {
    return {
        render: (element, controller) => {
            ...
        },
        update: (element, controller, list) => {
            ...
        }
    }
}

Регистрируется именно функция: платформа сама вызывает itemCards() и берет render и update из результата, поэтому нельзя регистрировать сам объект с этими функциями без функции, которая его возвращает. Её имя ищется сначала в реестре window.lsfusion.custom, где регистрируют свои экспорты загруженные клиентские модули JavaScript, затем среди имён глобального объекта window. Имя, зарегистрированное с видом reactView, — это компонент React.

Функция render принимает на вход контроллер и элемент, внутри которого должны создаваться новые элементы, необходимые для отображения данных.

Для группы объектов сигнатура функции — render(element, controller, event). При создании представления она получает событие браузера, открывшее форму, если оно ещё доступно, или null. Для ячейки свойства вызывается render(element, controller).

Для обновления отображаемых значений платформа будет каждый раз вызывать функцию update, в которую будет передан тот же element, что и в функции render, а также список значений list. Для свойства в update вместо списка передаётся его значение.

Объект может содержать и необязательную функцию clear, которую платформа вызывает при очистке представления группы объектов или ячейки свойства. Если clear группы выбросит исключение, клиент сообщит об ошибке и завершит очистку представления.

Прежнее объявление функции отображения группы с параметрами, function itemCards(element, list, controller), устарело с версии 5.0 и будет удалено в 8.0. Платформа вызывает такую функцию напрямую при каждом обновлении. Её заменяет показанная выше функция без параметров с инициализацией в render, передачей нового списка в update и очисткой в clear.

Строки группы объектов​

В list передается не весь набор объектов, а только считанная страница: для группы объектов с видом представления CUSTOM ее размер по умолчанию — 1000 объектов. Чтобы представление получало все объекты группы, задайте в блоке OBJECTS опцию PAGESIZE 0 (читать все объекты).

Названия полей объектов соответствуют названию свойств на форме. Если свойство группируется по колонкам, поле колонки с непустым ключом называется <property>_<index>, где index — позиция среди ключей колонок этого свойства, начиная с нуля. Поле колонки, скрытой по условию SHOWIF, в строке отсутствует.

Значения свойств преобразуются в значения JS так же, как в строках React-представления: например, значения классов даты и времени передаются как Date, а JSON — как разобранный объект. Свойство, значением которого является объект, приходит числовым id этого объекта — тем же, которым объект передаётся в запись FK и вызовы сервера.

Каждый объект содержит также те же key и objects, что и строка представления React (Идентификация строки). Имена key и objects зарезервированы для идентификации строки.

Четвёртым аргументом, options, функция update получает значение опции OPTIONS группы (разобранный JSON).

Текущий объект​

Если второй параметр changeObject (rendered) не указан, он считается равным false, что означает, что сервер должен в итоге вызвать функцию update с новым списком объектов (возможно тем же). Если представление уже отобразило новый текущий объект, передают rendered = true.

Если явно переданный объект, отличный от null, не удалось определить, текущий объект сохраняется. В этом случае, как и при передаче уже текущего объекта, вызов завершается без запроса. Если есть текущая строка, при передаче null в качестве object отправляется запрос, который завершается ошибкой, поскольку серверу нужен ключ строки.

Изменение свойств​

changeProperty понимает свои аргументы после property по их количеству, а единственный аргумент — по нему самому:

  • без аргументов он выполняет событие изменения свойства (для действия — само действие) на текущем объекте;
  • с одним аргументом он считает его строкой и выполняет на ней событие изменения, если это строка данных или дескриптор objects либо если свойство — действие, нарисованное в группе объектов; всё остальное — значение, которое устанавливается для текущего объекта;
  • с двумя аргументами он считает первый строкой, а второй — значением.

Формат значений — тот же, что у <group>.<property>.change контроллера формы.

Свойство, не являющееся колонкой этой группы, changeProperty передает форме, которая разрешает его только по имени — так, как представление называет свойство везде: <group>.<property> — свойство этой группы, имя без группы — свойство уровня формы (пустой группы); свойство группы объектов называется с группой, передана строка или нет, а строка, переданная с именем без группы, — ошибка.

Для колонки этой группы changeProperty(property, object, value[, type[, index]]) обновляет также список, запомненный методом diff, если такой список есть:

  • По умолчанию метод заменяет указанное поле в совпадающих строках.
  • С 'add' он вставляет копию объекта с заданным значением поля в позицию index (начиная с нуля, по умолчанию в конец).
  • С 'remove' удаляет совпадающую строку, которая должна быть в списке.

Эти аргументы влияют только на запомненный список.

Если явно переданная строка не содержит дескриптора и сама им не является, метод возвращает null и выводит причину в консоль. При передаче изменения форме неизвестное или неоднозначное имя, свойство с группировкой по колонкам либо строка, недопустимая для указанного имени, вызывают исключение в момент вызова.

Пакет​

batch(fn) делает несколько изменений вместе: каждый вызов changeProperty в fn делается сразу, а уходят они одним запросом, когда fn вернётся, — например, представление диаграммы Ганта при перетаскивании полосы задачи изменяет обе даты сразу:

controller.batch(() => {
    controller.changeProperty('start', task, newStart);
    controller.changeProperty('end', task, newEnd);
});

Пакет включает только изменения, а изменения — только через changeProperty и фильтры представления (setBooleanViewFilter, setDateIntervalViewFilter), которые входят в пакет: перевод фокуса или изменение DOM внутри fn заставляют платформу отправлять свои запросы, а на них пакет не рассчитан.

Внутри fn getPropertyValues отклоняется — вызывается его failure-callback, причина пишется в консоль, — а серверный вызов контроллера формы (controller.form.exec, eval, evalAction, change) — тоже, его Promise отвергается. Делайте их до пакета или после.

Функция, возвращающая Promise, отклоняется — но не собственный Promise пакета, который возвращает changeProperty, сделанный в fn, — как и в batch контроллера формы.

Поиск значений​

getPropertyValues использует те же режимы mode, что и <group>.<property>.getValues контроллера формы, но свойство разрешается среди колонок этой группы, а запрос выполняется для ее текущего объекта.

Результат передаётся в обработчик ok в виде { data: [ { displayString, rawString, objects }, ... ], more }. more равно true, пока будут ещё ответы — окончательный список ответа, который сервер дал, ещё не убедившись, что несохранённые изменения формы на него не влияют, или ответ более позднего запроса. Ответ более раннего запроса, пришедший после ответа более позднего, отбрасывается:

controller.getPropertyValues('name', query, result => { ... });

Оба метода поиска не возвращают значения. В ответе displayString — отображаемый текст подсказки, rawString — исходный текст, а objects зависит от режима поиска. При неизвестной колонке, неизвестном режиме или ошибке поиска вызывается fail(), если он передан. При неизвестном режиме причина также выводится в консоль. В getPropertyValues положительный count увеличивает число запрашиваемых подсказок. По умолчанию count равен 0. Сокращённый метод группы getValues всегда использует это значение.

Изменения списка​

Чтобы обновлять DOM только для изменившихся значений, у controller есть метод diff, в который передаются новый список объектов list и функция-обработчик. Метод сравнивает переданный список со списком из предыдущего вызова (при первом вызове — с пустым) и выдает изменения как последовательный сценарий преобразования старого списка в новый: обработчик вызывается для каждого изменения и получает:

  • его тип ('add', 'update' или 'remove');
  • позицию изменения в преобразуемом списке (для 'add' и 'update' она совпадает с позицией объекта в новом списке);
  • сам объект (для 'remove' — удаленный, для остальных типов — новый).

После этого переданный список запоминается.

Два необязательных флага уточняют сравнение:

  • При noDiffObjects строка одного объекта не превращается в строку другого — вместо 'update' такая пара дает 'remove' и 'add'.
  • При removeFirst обработчик получает сначала все удаления — с позициями в предыдущем списке — и только затем добавления и изменения.

Пример:

controller.diff(list, (type, index, object) => {
    switch (type) {
        case 'add': ...; break;
        case 'update': ...; break;
        case 'remove': ...; break;
    }
}, true, true);

Метод clearDiff сбрасывает запомненный список — его вызывают в необязательной функции clear компонента, которая вызывается при очистке представления с теми же element и controller, чтобы следующая отрисовка началась с пустого состояния.

Фильтры представления​

setBooleanViewFilter и setDateIntervalViewFilter задают серверный фильтр представления и размер страницы pageSize: в следующий вызов update список приходит уже отфильтрованным. setBooleanViewFilter оставляет объекты, у которых значение свойства property истинно. setDateIntervalViewFilter оставляет объекты, у которых период от значения startProperty до значения endProperty пересекается с интервалом от start до end (значения — JS Date, а если endProperty равен null, оба конца периода берутся из startProperty). Так, встроенное представление календаря читает только события видимого диапазона дат.

Если в фильтре представления указана неизвестная колонка, фильтр и размер страницы сохраняются.

Чтение значений и атрибутов дизайна​

Геттеры отображения позволяют компоненту использовать атрибуты дизайна, задаваемые на форме: например, представление диаграмм строит наборы данных, беря заголовок и цвета колонок из getCaption, getBackground и getForeground.

Геттеры колонки, принимающие объект, используют текущую строку, если объект не указан или равен null. Для неизвестной колонки геттеры значения и атрибутов дизайна, а также isPropertyReadOnly возвращают null.

Запросы​

При изменении в группе, установке фильтра представления или выполнении пакета Promise запроса разрешается после обработки клиентом ответа сервера. Если запрос отправлять не требуется, Promise разрешается сразу. При ошибке запроса или на закрытой форме (Form is closed) он отклоняется.

Правка формы — changeObject, changeProperty, batch и фильтры представления — использует обычный механизм правки и не требует проверки доступа. Вызовы сервера контроллера формы, controller.form, её проходят (Проверка доступа).

Значение свойства​

Функция отображения свойства рисует одно значение — значение своего свойства, в ячейке таблицы или на панели. Функция update получает его третьим аргументом, value:

update: function (element, controller, value) {
    element.text.innerText = value || '';
}

Значение любого класса приходит преобразованным в значение JS так же, как в строках React-представления, и, кроме файлов, в том же виде передаётся в change.

У обычной функции отображения ячейки, заданной в CUSTOM, четвёртый аргумент update равен null.

Вместе с SELECT функция отображения рисует выбор. В value функции update передаются варианты свойства, как и собственному элементу выбора платформы. Зарегистрированная функция вызывается с объектом {multi, notNull, html, changeValue}: multi означает выбор нескольких значений, notNull — обязательность выбранного значения, html — представления вариантов в виде HTML, а changeValue — передачу представления выбранного варианта явному изменению свойства.

Контроллер свойства​

changeProperty(property, object, newValue[, type[, index[, changeValue]]])изменяет поле элемента массива в ячейке. Передаёт в change объект {property, objects: object.objects, value: newValue} либо явно заданное значение changeValue. Отображаемый массив обновляется, как описано ниже
getValues(value, ok[, fail[, count]])список подсказок с сервера для вводимого значения value — тех же, что при штатном редактировании свойства
getPropertyValues(property, value, ok[, fail[, count]])вызывает getValues ячейки со строкой поиска property + ':' + value. Для стандартного действия изменения свойства, построенного оператором JSON, property — интеграционное имя поля, значения которого запрашиваются
isReadOnly()доступность свойства для правки: null — редактируемое, false — только чтение, true — отключено
isList()false для свойства, в том числе в ячейке таблицы
isTabFocusable()должно ли поле ввода представления получать фокус при переходе по Tab. На панели определяется доступностью фокуса для свойства, в ячейке таблицы равно false

getObjectsString(object)значение, по которому diff и changeProperty сопоставляют элементы
diff(list, fnc[, noDiffObjects][, removeFirst])вычисляет изменения массива значений — как метод diff группы объектов; элементы сопоставляются по полю objects

Для строки платформы или её дескриптора getObjectsString учитывает идентификаторы объектов группы и ключ строки. Если передать null или не передать элемент, возникает TypeError. Для другого объекта с заданным key метод возвращает String(object.key). В остальных случаях он возвращает null, если поле object.objects отсутствует, равно undefined или null. При любом другом значении поля метод возвращает результат JSON.stringify(object.objects) (например, JSON.stringify(() => 1) возвращает undefined) или '{}', если при сериализации выброшено исключение.

Значение, переданное методом change, попадает в обработку изменения свойства так же, как значение, введенное штатным редактором, — для первичного свойства это запись значения в него. Когда переданный объект попадает в стандартное действие изменения свойства со значением пользовательского класса, указанного в блоке CHECKED BY ограничения, он должен быть среди значений, которые оставляет фильтр: иначе изменение отклоняется.

Если после свойства указано действие с ключевым словом ON CHANGE, вместо стандартной обработки изменения выполняется оно, а значение, переданное методом change, подставляется вместо ввода пользователя в его запрос значения.

Запросы метода change и вызовов сервера через controller.form выполняются на сервере в порядке вызова.

Методы ячейки change, changeValue и changeProperty не возвращают значения. Для changeProperty исходный отображаемый массив пуст, если старое значение равно null. По умолчанию у совпадающих элементов заменяется указанное поле. Операции 'add' и 'remove' и позиция вставки index действуют так же, как у changeProperty группы объектов. Явно заданный changeValue влияет только на значение, переданное действию.

Обработчик ok метода getValues получает результат в том же формате, что и getPropertyValues пользовательской группы объектов. Оба метода поиска ячейки не возвращают значения и принимают такие же count и обработчик ошибки. Чтобы указать count без обработчика ошибки, используйте controller.getPropertyValues('name', query, ok, undefined, 20). При поиске внутри пакета вызывается fail(), если он передан, и причина выводится в консоль.

Если функция отображения свойства рисует подвал колонки или ячейку сводной таблицы, изменение и поиск не выполняются и ни один обработчик поиска не вызывается. Если функция отображения рисует значение пользовательского фильтра, change(value, renderValueSupplier) записывает в фильтр результат renderValueSupplier(oldValue), где oldValue — текущее значение фильтра. В пользовательском фильтре ни getValues, ни getPropertyValues не вызывают ok или fail.

Функция render и необязательная функция clear, вызываемая при очистке ячейки, получают вторым аргументом сокращенный контроллер. Он предоставляет isList(), isTabFocusable() и clearDiff(), сбрасывающий запомненный методом diff список. Метод isReadOnly() полного контроллера возвращает состояние на момент вызова update.
