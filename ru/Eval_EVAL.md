# Выполнение программного кода (EVAL)

Оператор выполнения программного кода создает [действие](/ru/Actions.md), которое во время работы сервера компилирует строку с исходным кодом на языке lsFusion и выполняет её внутри сервера с полным доступом к остальному проекту.

### Исходный код[​](#исходный-код "Прямая ссылка на этот заголовок")

Строка трактуется как тело свежего [модуля](/ru/Modules.md), сгенерированного платформой. Заголовок модуля платформа формирует автоматически: уникальное имя модуля плюс зависимости от всех загруженных на этот момент модулей. В режиме инструкций код может задавать пространство имён модуля и приоритеты пространств имён. Поэтому код может ссылаться на любой [элемент](/ru/Element_identification.md) проекта и сам объявлять новые локальные элементы. По умолчанию пространство имён сгенерированного модуля совпадает с его уникальным именем, а пространство имён и [приоритеты поиска](/ru/Search_.md#priority) вызывающего модуля не наследуются: если код не задаёт пространство имён или приоритеты, при поиске имени без пространства имён ни одно пространство имён проекта не имеет предпочтения.

Код, который компилирует оператор выполнения программного кода, компилируется под ещё одним кодом и видит его элементы вместе с тем, что видит этот код: под самым внутренним из выполняющихся кодов, скомпилированных во время работы сервера — другим таким оператором или полученных через [Action API](/ru/Access_from_an_external_system.md), — и кодом [формы](/ru/Forms.md), действие которой выполняется, — кодом, настроившим форму, иначе тем, что видит код, открывший её; в потоке, запущенном на сервере [новым потоком](/ru/New_threads_NEWTHREAD_NEWEXECUTOR.md), — тем, что видит запустивший его код; если ничего из этого нет — кодом настройки приложения. Код, настраивающий форму, компилируется так же — под тем, что видит код, открывающий форму. Код, отправленный в другое соединение, выполняется там с тем, что видит это соединение. Как и у модулей проекта, у этих элементов нет приоритета: имя без пространства имён, которое объявляют и они, и проект, неоднозначно.

Принимаются две формы исходного кода — в зависимости от режима оператора:

* *Режим инструкций* (по умолчанию). Строка является последовательностью инструкций. Одна из них должна создавать действие с именем `run` — именно оно и будет выполнено. Как обычное скриптовое действие, `run` может объявлять интерфейсные параметры и получать через них значения.
* *Режим действия*. Строка трактуется как тело действия — последовательность [операторов-действий](/ru/Action_operators_paradigm.md) и объявлений локальных свойств, — которое платформа автоматически оборачивает в действие `run`. Частей заголовка модуля и других инструкций уровня модуля в этой строке быть не может. Тело обращается к runtime-аргументам eval-действия позиционно.

### Параметры[​](#параметры "Прямая ссылка на этот заголовок")

Действие, выполняющее программный код, принимает исходный код как свой первый параметр. Дополнительные значения, передаваемые оператору, становятся runtime-аргументами `run` при его вызове и подчиняются обычным правилам передачи параметров.

### Область выполнения[​](#область-выполнения "Прямая ссылка на этот заголовок")

Скомпилированное действие `run` выполняется синхронно в [сессии](/ru/Change_sessions.md) вызывающего действия, поэтому его чтения и записи разделяют сессию, apply и транзакционное состояние с вызывающим.

### Ограничения на выполняемый код[​](#ограничения-на-выполняемый-код "Прямая ссылка на этот заголовок")

Выполняемый код предназначен для добавления новых локальных элементов и вызова существующих. Постоянную структуру проекта он менять не может. В коде eval не могут появляться:

* объявления новых [классов](/ru/Classes.md), [таблиц](/ru/Tables.md) и [индексов](/ru/Indexes.md)
* глобальные [события](/ru/Events.md) и [ограничения](/ru/Constraints.md), включая формы write-события и follows-ограничения, привязанные к объявлению свойства, а также ограничение, которое неявно создаёт [рекурсия](/ru/Recursion_RECURSION.md) с политикой `CYCLES NO` (действующей по умолчанию)
* [агрегации](/ru/Aggregations.md), а также режимы агрегации и равенства у [группировки](/ru/Grouping_GROUP.md)
* [материализация](/ru/Materializations.md), явное размещение в таблице и not-null ограничения на свойствах
* объявление [группы](/ru/Groups_of_properties_and_actions.md) с родительской группой из другого модуля или привязка свойства или действия к группе из другого модуля
* добавление базовых событий к существующим действиям
* [абстрактные](/ru/Property_extension.md) свойства и действия: добавление реализации объявленному вне кода, а также объявление в коде и использование объявленного
* настройка [навигатора](/ru/Navigator.md), в том числе планирование его действий, а также создание или скрытие его [окон](/ru/Navigator_design.md)
* назначение [обработки события формы](/ru/Form_events.md#property) по умолчанию для свойства или действия, а также добавление аспекта, который выполняется до или после существующего действия

[Data-свойства](/ru/Data_properties_DATA.md), объявленные внутри eval-кода, приводятся к области сессии. Постоянные data-объявления не допускаются.

### Язык[​](#язык "Прямая ссылка на этот заголовок")

Для создания действия, выполняющего программный код, используется [оператор `EVAL`](/ru/EVAL_operator.md).

[Инструкция `NAVIGATOR`](/ru/NAVIGATOR_statement.md) настраивает навигатор и позволяет планировать периодические действия с помощью `SCHEDULE`. [Инструкции `WINDOW` и `HIDE WINDOW`](/ru/WINDOW_statement.md) создают и скрывают окна соответственно.

[Опция действия `ASON`](/ru/Action_options.md) задаёт обработку события формы по умолчанию. Инструкции [`BEFORE`](/ru/BEFORE_statement.md) и [`AFTER`](/ru/AFTER_statement.md) добавляют действия, которые выполняются соответственно до и после существующего действия.

### Примеры[​](#примеры "Прямая ссылка на этот заголовок")

```
// тело действия задано напрямую
addProperty { EVAL ACTION 'MESSAGE \'Hello World\''; }

// произвольный скрипт, введённый пользователем
code 'Исходный код' = DATA BPSTRING[2000] ();
execute 'Выполнить код' { EVAL code(); }

// передача runtime-аргумента в выполняемое тело в режиме действия
greet 'Поприветствовать пользователя' (CustomUser u) { EVAL ACTION 'MESSAGE \'Здравствуй, \' + name($1);' PARAMS u; }

// внутренний код видит свойство, объявленное внешним кодом
nested 'Вложенный код' { EVAL 'answer() = 42; run() \{ EVAL ACTION \'MESSAGE answer();\'; \}'; }
```
