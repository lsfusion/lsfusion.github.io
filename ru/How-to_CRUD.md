# How-to: CRUD

## Пример 1[​](#пример-1 "Прямая ссылка на этот заголовок")

### Условие[​](#условие "Прямая ссылка на этот заголовок")

Есть множество предопределенных типов книг.

```
CLASS Type 'Тип' {
    novel 'Роман',
    thriller 'Триллер',
    fiction 'Фантастика'
}
name 'Наименование' (Type g) = caption(g) IF g IS Type;
```

Необходимо создать форму для выбора типа из списка.

### Решение[​](#решение "Прямая ссылка на этот заголовок")

```
FORM types 'Список типов'
    OBJECTS g = Type
    PROPERTIES(g) READONLY name

    LIST Type OBJECT g
;
```

Конструкция `LIST` обозначает, что данная форма будет использоваться при необходимости выбора списка типов (например, при попытке изменения типа для книги).

## Пример 2[​](#пример-2 "Прямая ссылка на этот заголовок")

### Условие[​](#условие-1 "Прямая ссылка на этот заголовок")

Есть набор книг с заданными наименованиями.

```
CLASS Book 'Книга';
name 'Наименование' = DATA ISTRING[30] (Book) IN id;
```

к сведению

Следует отметить, что все свойства `name` рекомендуется добавлять в группу `id`. Значения этого свойства будут идентифицировать объект в случае нарушения ограничения. Также оно будет добавлено на автоматические формы, если для класса не будут заданы формы редактирования и выбора.

Необходимо создать форму со списком книг, с возможностью их добавления, редактирования и удаления.

### Решение[​](#решение-1 "Прямая ссылка на этот заголовок")

```
FORM book 'Книга' // форма для отображения "карточки" книги
    OBJECTS b = Book PANEL
    PROPERTIES(b) name

    EDIT Book OBJECT b
;

FORM books 'Книги'
    OBJECTS b = Book
    PROPERTIES(b) READONLY name
    PROPERTIES(b) NEWSESSION NEW, EDIT, DELETE

    LIST Book OBJECT b
;

NAVIGATOR {
    NEW books;
}
```

## Пример 3[​](#пример-3 "Прямая ссылка на этот заголовок")

### Условие[​](#условие-2 "Прямая ссылка на этот заголовок")

Есть набор жанров книг с заданными наименованиями.

```
CLASS Genre 'Жанр';
name 'Наименование' = DATA ISTRING[30] (Genre);
```

Необходимо создать форму со списком жанров, с возможностью их добавления, редактирования и удаления, и отдельную форму для выбора без такой возможности.

### Решение[​](#решение-2 "Прямая ссылка на этот заголовок")

```
FORM genre 'Жанр'
    OBJECTS g = Genre PANEL
    PROPERTIES(g) name

    EDIT Genre OBJECT g
;

FORM genres 'Жанры'
    OBJECTS g = Genre
    PROPERTIES(g) READONLY name
    PROPERTIES(g) NEWSESSION NEW, EDIT, DELETE
;

FORM dialogGenre 'Жанры'
    OBJECTS g = Genre
    PROPERTIES(g) READONLY name

    LIST Genre OBJECT g
;

NAVIGATOR {
    NEW genres;
}
```

Такая схема (с тремя формами, вместо двух) наиболее подходит для того, чтобы отключить возможность редактирования жанров при их выборе, с целью минимизировать вероятность случайного исправления пользователем информации о жанрах. В таком случае, изменять жанры можно только на специальной форме.

## Пример 4[​](#пример-4 "Прямая ссылка на этот заголовок")

### Условие[​](#условие-3 "Прямая ссылка на этот заголовок")

Аналогично [**Примеру 2**](#%D0%BF%D1%80%D0%B8%D0%BC%D0%B5%D1%80-2). Нужна одна карточка книги, на которой пользователь либо выбирает существующую книгу, либо создает новую, а затем редактирует ее реквизиты.

```
pages 'Страниц' = DATA INTEGER (Book);
```

### Решение[​](#решение-3 "Прямая ссылка на этот заголовок")

```
FORM bookCard 'Книга'
    OBJECTS b = Book PANEL NULL
    PROPERTIES(b) book 'Книга' = name SELECTOR, NEW
    PROPERTIES(b) name, pages
;

DESIGN bookCard {
    // блок выбора: поле выбора книги и кнопка создания в одну строку
    NEW selection FIRST {
        caption = 'Выбор книги';
        horizontal = TRUE;
        MOVE PROPERTY(book);
        MOVE PROPERTY(NEW(b));
    }
    // реквизиты выбранной или созданной книги
    NEW details AFTER selection {
        caption = 'Реквизиты';
        MOVE PROPERTY(name(b));
        MOVE PROPERTY(pages(b));
    }
}

NAVIGATOR {
    NEW bookCard;
}
```

Тип объектов по умолчанию `NULL` открывает карточку без текущей книги. Поле выбора книги (`SELECTOR`) при изменении не редактирует наименование, а открывает диалог выбора книги, поэтому наименование добавлено на форму еще раз — обычным редактируемым полем. Чтобы два наименования не путались, дизайн разводит их по блокам: в блоке «Выбор книги» поле выбора стоит в одну строку с кнопкой создания, в блоке «Реквизиты» — редактируемые наименование и число страниц. Пока книга не выбрана и не создана (`NEW`), из свойств объекта `b` на форме видно только поле выбора: остальные свойства и действия, принимающие `b`, не показываются, поскольку объекта, к которому они относятся, нет, а пустой блок реквизитов скрыт. Как только пользователь выбирает или создает книгу, появляются наименование и число страниц, и их можно редактировать. Если все поля должны быть доступны с самого открытия, объект нужно создать заранее и открыть карточку уже для него — как это делает действие `NEWSESSION NEW` в [**Примере 2**](#%D0%BF%D1%80%D0%B8%D0%BC%D0%B5%D1%80-2).
