# How-to: Пользовательские клиентские модули JS

В этой статье собраны типовые задачи, решаемые клиентскими модулями JavaScript, — каждая со своим решением. Сами модули описаны в статье [Клиентские модули JavaScript](/ru/Client_JavaScript_modules.md).

### Папка для файла[​](#file-folder "Прямая ссылка на этот заголовок")

Нужно выбрать, куда положить файл клиентского кода — в *src/main/web* для сборки или в *src/main/resources/web* без неё — и как он будет загружаться ([Файлы без сборки](/ru/Client_JavaScript_modules.md#without-the-build)).

**Автоматически — поместите его в *resources/web/init*.** Подходит для самодостаточного компонента или таблицы стилей.

**Явно — перечислите его в *onWebClientInit*.** Используйте это, когда важен порядок загрузки — сторонняя библиотека должна загрузиться раньше использующего её компонента — или для условной загрузки файла.

Для большого файла *.jsx* без сборки задайте `jsxTransformTimeout` больше времени его преобразования или перенесите компонент на собираемый уровень *src/main/web*, где он преобразуется при сборке ([Файлы .jsx без сборки](/ru/Client_JavaScript_modules.md#lightweight-jsx)).

### Функция для клиентского действия[​](#example "Прямая ссылка на этот заголовок")

Нужно действие, которое форматирует сумму заказа на клиенте функцией JavaScript из проекта. Решение использует именованный экспорт модуля, который компилирует сборка ([Именованные экспорты и автоматическая регистрация](/ru/Client_JavaScript_modules.md#named-exports-and-auto-registration)).

Поместим небольшой модуль в *src/main/web/orderUtil.js*, экспортирующий функцию форматирования:

```
export function formatSum(amount, currency) {
    return new Intl.NumberFormat("en-US", { style: "currency", currency }).format(amount);
}
```

Привяжем его к клиентскому действию и вызовем:

```
formatOrderSum 'Format' (Order o) {
    INTERNAL CLIENT 'formatSum' PARAMS sum(o), 'USD';
}
```

Сборка компилирует *orderUtil.js* в *web/.compiled/orderUtil.js* и регистрирует `formatSum`. При открытии формы действие находит имя в реестре и вызывает функцию. Запись в *onWebClientInit* для модуля не пишется.

### Стили компонента[​](#component-styles "Прямая ссылка на этот заголовок")

Нужно оформить компонент модуля, который компилирует сборка ([Стили](/ru/Client_JavaScript_modules.md#styles)).

Рекомендуемый способ оформления:

* **CSS-модули** (`import styles from "./Component.module.css"`, применяется как `className={styles.root}`) для собственных стилей компонента.
* **Inline-стили `style={{ ... }}`** для значений, вычисляемых из данных (цвета и размеры по строке, условное оформление).
* Обычный `import "./Component.css"` (или CSS сторонней библиотеки) для библиотечных или намеренно глобальных стилей, с префиксом в именах классов. Скомпилированный *.css* не нужно регистрировать вручную — он уже загружается автоматически.

Для полноценной системы стилей помимо статических классов подключите библиотеку CSS-in-JS времени выполнения (например, `styled-components` или `@emotion`) зависимостью `org.mvnpm`. Используйте API `styled` или `className={css(...)}`.

Нативный CSS (вложенность, пользовательские свойства) и CSS-модули покрывают большую часть того, ради чего применялись препроцессоры. Если препроцессор CSS (Sass/SCSS, Less, Stylus) или утилитарный фреймворк (Tailwind, UnoCSS) всё же нужен, сгенерируйте CSS отдельным шагом и поставьте результат обычной таблицей стилей через `onWebClientInit`.

### Цвета для тёмной темы[​](#dark-theme-colors "Прямая ссылка на этот заголовок")

Нужно, чтобы цвета компонента следовали цветовой теме интерфейса. Решение использует атрибут `data-bs-theme` корневого элемента страницы ([Стили](/ru/Client_JavaScript_modules.md#styles)). Основные правила задают цвета светлой темы, а правила, адресованные по атрибуту, переопределяют их в тёмной.

```
.board { background: #ffffff; color: #212529; }
[data-bs-theme="dark"] .board { background: #212529; color: #dee2e6; }
```
